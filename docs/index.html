How it works

One Helm install.
Everything else is automatic.

openserve reconciles your intent — declared as Kubernetes CRDs — into GPU pods, routes, rate limits, and budget guardrails. You manage the what; openserve handles the how.

01

helm install

Deploy the operator, gateway, control-api, and GUI into your existing GKE cluster. Connects to your Cloud SQL, Redis, and GCS bucket.

02

Browse catalog

Pick from 25+ vetted open-source models — Llama 3, Mistral, Phi-3, Gemma, Qwen, and more. Weights are cosign-verified before the pod starts.

03

Deploy a model

One click (or one API call). The operator provisions a vLLM pod on a GPU node, hooks KEDA for scale-to-zero, and exposes a ClusterIP service.

04

Create an API key

Generate scoped keys with RPM + TPM rate limits, optional expiry, and IP allowlist. Argon2id-hashed — the raw value is shown once.

05

Call the model

Point any OpenAI SDK at your domain. The gateway validates the key, enforces limits, and streams the response — all inside your VPC.

Internet → Cloud Armor → Load Balancer → openserve-gateway

                          ┌─────────────────────────┴──────────────────────────┐
                          │  1. validate API key  (Postgres / Argon2id)        │

Features

Everything you need.
Nothing you don't.

🔒

Data sovereignty

Every prompt and response stays inside your GCP VPC. No data flows to any third-party inference provider — ever.

⚡

Scale to zero

KEDA watches vllm_num_requests_running. Idle deployments automatically scale to 0 replicas and cold-start on the next request.

💰

Hard budget caps

Set a BudgetPolicy with a daily USD ceiling. When spend exceeds the cap, the operator automatically scales replicas to 0 and pauses the deployment.

🔑

Per-key rate limits

Each API key has independent RPM and TPM counters via a Redis sliding-window. Actual token counts (not just request counts) are tracked post-stream.

🤝

OpenAI-compatible

Point any openai SDK at your domain by setting base_url. Drop-in replacement for existing LLM integrations.

🔄

LoRA adapters

Hot-load fine-tuned LoRA adapters into a running vLLM pod without redeployment. List them in spec.loraAdapters on any ModelDeployment.

🧠

Prefix-cache routing

The gateway hashes the system prompt and uses consistent hashing to route requests to the same pod — maximising the KV cache hit rate.

🔍

Built-in RAG

Upload documents via the control-api. Embeddings are stored in pgvector (IVFFlat index, cosine similarity) and retrieved at query time.

📋

Immutable audit log

Every action is append-only in Postgres, mirrored to a Cloud Logging bucket with bucket lock. Monthly hash-chain anchors prevent retroactive tampering.

🔌

Multi-engine support

Set spec.engine: sglang on any ModelDeployment to use SGLang instead of vLLM — recommended for structured generation and long-context workloads.

🌐

Multi-provider OIDC

Set OIDC_ISSUER_URL to any RFC 8414 provider — Google Workspace, Okta, Azure AD, or GitHub Actions. No code changes required.

🔗

Peer relay

Connect external partner inference nodes via WebSocket. Route requests to partner-hosted models through a dedicated peer-relay service.

Quick start

From zero to inference
in under 5 minutes.

bash — Helm install 
# Add the Helm repo
helm repo add openserve https://charts.openserve.io
helm repo update

# Install into your GKE cluster
helm install openserve openserve/openserve \
  --namespace openserve-system --create-namespace \
  --set domain=ai.acme.com \
  --set google.clientId=123456789.apps.googleusercontent.com \
  --set postgres.host=10.0.0.5 \
  --set postgres.secret=openserve-postgres-secret \
  --set redis.host=10.0.0.6 \
  --set gcs.bucket=acme-openserve-models \
  --set billing.bigqueryDataset=openserve_usage

# Browse to https://ai.acme.com and sign in with Google Workspace
bash — Deploy Llama 3 8B via API 
# One click from the GUI: Catalog → Llama 3 8B Instruct → Deploy
# Or via the control-api REST endpoint:

curl -X POST https://ai.acme.com/api/v1/deployments \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "modelRef": "llama-3-8b-instruct",
    "gpuClass": "l4",
    "scaleToZero": true,
    "idleTimeoutMin": 10,
    "maxReplicas": 2,
    "budget": {"dailyUsdCap": "50"},
    "limits": {"maxInputTokens": 8192, "maxOutputTokens": 4096}
  }'

# Poll until phase=Running (typically 2–4 min while weights download)
curl https://ai.acme.com/api/v1/deployments/<id> \
  -H "Authorization: Bearer $ADMIN_TOKEN" | jq .status.phase
bash — Create a scoped API key 
# Create a key — raw value shown once, Argon2id-hashed at rest
curl -X POST https://ai.acme.com/api/v1/keys \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"displayName": "prod-app-key"}'

# Response:
{
  "key": "openserve_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "id":  "01HXY..."
}

# Save the key — it will NOT be shown again.
# Default limits: 60 RPM, 100,000 TPM.  Adjust in the GUI or PATCH /api/v1/keys/:id
bash / python — Call the OpenAI-compatible API 
# curl (streaming SSE)
curl https://ai.acme.com/inference/llama-3-8b-instruct/v1/chat/completions \
  -H "Authorization: Bearer openserve_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama-3-8b-instruct",
    "messages": [{"role":"user","content":"Explain BYOC in one sentence."}],
    "stream": true
  }'

# Python — drop-in OpenAI SDK usage
from openai import OpenAI

client = OpenAI(
    base_url="https://ai.acme.com/inference/llama-3-8b-instruct",
    api_key="openserve_live_xxx",
)
response = client.chat.completions.create(
    model="llama-3-8b-instruct",
    messages=[{"role": "user", "content": "Hello!"}],
    stream=True,
)
for chunk in response:
    print(chunk.choices[0].delta.content, end="", flush=True)
bash — Local development (Docker Compose) 
# Clone and run the full stack locally (no Kubernetes required)
git clone https://github.com/openserve/openserve
cd openserve

cp .env.dev.example .env.dev   # DEV_EMAIL=dev@localhost is already set

docker compose --env-file .env.dev up --build

# The mock-vllm service simulates a real inference backend
# Ports: control-api :8080 · gateway :8081 · GUI :3000 · mock-vllm :8000

# Run the end-to-end demo (catalog → key → inference → rate-limit → audit)
bash hack/local-demo.sh

Security

Built for compliance
from day one.

openserve is designed to help teams achieve SOC 2, HIPAA, and FedRAMP readiness — because you control the infrastructure.

🔐

Argon2id key hashing

API key raw values are hashed with Argon2id (time=1, mem=64 MB, threads=4) and discarded. Never stored in plain text.

✅

Weight integrity

Model weights are verified against cosign-signed SHA256 manifest entries before any inference pod starts. Supply chain attacks detected before load.

🛡️

Network isolation

vLLM pods have a NetworkPolicy that allows egress only to GCS private access (199.36.153.8/30). Compromised models cannot phone home.

📝

Immutable audit log

All actions are append-only in Postgres + Cloud Logging bucket lock. Monthly hash-chain anchors make retroactive log tampering detectable.

🔑

No static SA keys

All GCP API access uses Workload Identity. Zero long-lived service account JSON keys in the cluster.

🔒

Private networking

Cloud SQL and Redis use private IP only — never public endpoints. All intra-cluster traffic is mTLS via cert-manager.

💵

Budget auto-pause

BudgetPolicy CRD polls BigQuery spend every 5 minutes. When the daily cap is breached, the operator scales replicas to 0 immediately.

🌐

CMEK encryption

Model weights in GCS are encrypted with customer-managed encryption keys. You hold the keys — Anthropic, Google, and openserve cannot decrypt them.
